# Terra Runner 1.4 — Windows / PowerShell 7

Автономный цикл OpenCode Build для Erranix NTD: один запуск = одна проверяемая итерация → тесты → commit → push; PowerShell повторяет запуск, отслеживает расходы, пишет отдельные логи и отчёты **по каждому проекту**.

## Быстрый старт v1.4: запуск без командной строки

**Дважды щёлкни по `Terra Runner.cmd`.** Автоматически откроется окно терминала с русским меню, настройками бюджета, модели, проектов и логов. Существующая конфигурация сохраняется. Подробности и тесты — в [`README-v1.4.md`](README-v1.4.md).

Приоритет первого запуска после обновления: открыть меню, выполнить пункт **3 (DryRun)**, затем пункт **1 (одна итерация)**. После проверки — пункт **2 (автономный цикл)**.

---

## Содержимое

- `terra-runner.ps1` — управление OpenCode, режимами бюджета и Git-проверками.
- `terra-worker.ps1` — отдельный процесс одного запуска OpenCode, UTF-8 вывод.
- `terra-prompt.md` — промпт одной законченной итерации.
- `terra-config.json` — пример полной конфигурации v1.3; по умолчанию **daily**.
- `tests/terra-selftest.ps1` и `tests/mock-opencode.ps1` — офлайн-проверки с локальным Git remote, без расходов API.
- `data/projects/<project>/logs/YYYY-MM-DD/` — логи, отчёты итераций (создаются автоматически).
- `data/projects/<project>/reports/YYYY-MM-DD.md` и `.json` — отчёт по проекту за день (создаются автоматически).
- `data/projects/<project>/control-state.json` — счётчики итераций без прогресса.
- `data/projects/budgets/<balance-id>.json` — снимок начального баланса, общий для проектов с одним `balance.id`.

> Файлы настроек с ключами и реальные данные сервисов в Git не добавлять. Каталог `data/` должен оставаться локальным и не публиковаться; JSONL может содержать полные ответы агента и секретные фрагменты файлов.

## Установка обновления

Папка Runner (отдельно от папки NTD):

`D:\Cloud\Разработка\Сайты\Проекты\erranix.agency\terra-runner`

Если ранее использовалась v1.1, **патч обновляет только скрипты, тесты и README**. Твой `terra-config.json` патч **не перезаписывает**. В него нужно вручную добавить `"mode"` и при желании раздел `"balance"` из `terra-config.v1.3.example.json`.

Старый `schemaVersion: 1` без `budget.mode` остаётся совместимым и ведёт себя как `daily`.

Требования: **PowerShell 7+** (`pwsh`), OpenCode 2 с `stats --json`, Git, работающий `origin`, чистый рабочий каталог ветки `codex/terra`.

```powershell
pwsh
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\tests\terra-selftest.ps1
.\terra-runner.ps1 -DryRun
.\terra-runner.ps1 -Once
.\terra-runner.ps1
```

## Четыре режима бюджета

В `terra-config.json` меняется **только** `budget.mode`.

| Режим | Что контролирует | Нужно устанавливать баланс? |
|---|---|---|
| `daily` | Расходы сегодня по общей локальной статистике OpenCode. Сохраняет старую логику $5/сутки | Нет |
| `balance` | Оценку остатка на аккаунте. Без каких-либо суточных лимитов | Да, при `source=snapshot` |
| `hybrid` | Одновременно суточный лимит и остаточный баланс. Остановка при достижении любого | Да, при `source=snapshot` |
| `unlimited` | Без денежного ограничения в Runner, но остаются лимиты итераций, ошибок и времени | Нет; обязательно `allowUnlimited: true` |

### A. Дневной лимит (по умолчанию)

```json
"budget": {
  "mode": "daily",
  "dailyUsd": 5.0,
  "reserveUsd": 0.5,
  "emergencyStopUsd": 4.95,
  "requireGlobalOpenCodeStats": true,
  "stopOnZeroCostWithTokens": true
}
```

Новая итерация не стартует при расходе от `$4.50`; во время работы текущей итерации предусмотрена остановка от `$4.95`. Фактический расход может превысить порог внутри запроса модели.

### B. Работа до остатка $5 (без суточного лимита)

Добавь в `budget` (сохрани имеющиеся `requireGlobalOpenCodeStats` / `stopOnZeroCostWithTokens`):

```json
"mode": "balance",
"balance": {
  "source": "snapshot",
  "id": "openai-main-account",
  "minimumUsd": 5.0,
  "iterationReserveUsd": 0.5
}
```

Сначала **проверь фактический остаток у своего провайдера**. Например, он равен `$100.00`. Выполни однократно:

```powershell
.\terra-runner.ps1 -SetBalanceUsd 100.00
.\terra-runner.ps1 -Status
.\terra-runner.ps1 -DryRun
.\terra-runner.ps1
```

Runner запоминает фактическое значение на момент замера и суммарный **накопленный расход локального OpenCode** на тот момент. Формула после начальной фиксации:

`расчётный остаток = подтверждённый вручную остаток − (OpenCode all-time сейчас − OpenCode all-time при фиксации)`

Например, баланс `$100`, минимум `$5`, резерв на итерацию `$0.50`: новую итерацию можно начать, пока оценка остатка **больше `$5.50`**. Во время выполнения Runner пытается прервать работу при достижении `$5`. **Дневного лимита в этом режиме нет.**

Если пополнил баланс, появились дополнительные списания вне OpenCode или изменился API-провайдер, нужно заново сверить фактический остаток и выполнить:

```powershell
.\terra-runner.ps1 -SetBalanceUsd 150.00 -ReconcileBalance
```

Предыдущая фиксация сохраняется в `data/projects/budgets/openai-main-account.history.jsonl`.

**Ограничения snapshot:** это **локальная оценка**, не live-баланс. OpenCode `stats --all --json` не видит запросы вне OpenCode, внешние списания, пополнения, истечение кредитов и может содержать расчётные цены BYOK. При смене компьютера/хранилища статистики или обнулении накопленного счётчика Runner блокирует запуск до сверки. Для точного ограничения средств используй лимиты провайдера (если они доступны) либо `balance.source=command` с проверяемым источником.

### C. Сочетание обоих ограничений

```json
"mode": "hybrid",
"dailyUsd": 5.0,
"reserveUsd": 0.5,
"emergencyStopUsd": 4.95,
"balance": {
  "source": "snapshot",
  "id": "openai-main-account",
  "minimumUsd": 5.0,
  "iterationReserveUsd": 0.5
}
```

Старт итерации разрешён только при выполнении **обоих** условий. Баланс инициализируется так же, как для `balance`.

### D. Без денежных ограничений

```json
"mode": "unlimited",
"allowUnlimited": true
```

Применяй осознанно: это снимает **денежные** ограничения Runner, но не ограничения OpenCode, провайдера и максимального времени/числа итераций.

## Необязательный источник актуального баланса

`balance.source = "command"` позволяет подключить внешний авторитетный провайдерский источник **без выдуманного API**:

```json
"balance": {
  "source": "command",
  "id": "account-main",
  "minimumUsd": 5.0,
  "iterationReserveUsd": 0.5,
  "maxAgeMinutes": 5,
  "command": "C:\\Scripts\\my-provider-balance.ps1",
  "arguments": []
}
```

Команда должна завершиться с exit code 0 и вернуть **только JSON**:

```json
{"balanceUsd": 42.10, "observedAt": "2026-11-03T20:00:00+03:00"}
```

Внешний скрипт тебе нужно реализовать самостоятельно, если провайдер действительно даёт разрешённый API баланса; не подставляй придуманное число и не делай команду, читающую устаревший локальный файл без пометки. Скрипт должен быть исполняемым и находиться в PATH или использовать поддерживаемый исполняемый путь; для `.ps1` удобно указать `"command": "pwsh"` и `"arguments": ["-NoProfile", "-File", "C:\\Scripts\\my-provider-balance.ps1"]`. Недоступная, нечисловая или устаревшая статистика **останавливает** Runner.

## Отчёты, ошибки инструментов, прогресс кода

Начиная с v1.3 каждая итерация сохраняет:

- `.events.jsonl` — исходный журнал, не изменяется.
- `.events.readable.jsonl` — отдельная попытка исправить типичное искажение UTF-8 ↔ CP866 в текстовых полях. Не все повреждения автоматически восстановимы.
- `.stderr.log` — stderr OpenCode.
- `.summary.json` — exit code, реальные Git HEAD, push, стоимость, токены, завершённые TODO, **ошибки инструментов** (`toolErrors`), изменения кода/тестов/документации.

Дневная сводка: `data/projects/ntd-terra/reports/YYYY-MM-DD.md` и `.json`. Сводка переписывается по текущему набору сохранённых итераций, отдельные project-логи не смешиваются.

```powershell
.\terra-runner.ps1 -Report
.\terra-runner.ps1 -Report -ReportDate 2026-11-03
.\terra-runner.ps1 -Status
```

В отчёте отдельно считаются исполняемый код, тесты и документация. Серия `maxConsecutiveDocumentationOnly` (по умолчанию 12) итераций только с документами автоматически останавливает Runner для ревью; это не означает, что архитектурные документы бесполезны. `maxConsecutiveNoProgress` (3) применяется **между перезапусками**, а не только в рамках одного запуска.

Ротация — отдельно для каждого проекта: `retainDays: 21`, `maxIterationsPerProject: 150`, `maxTotalMiBPerProject: 300`; отдельная ротация дневных отчётов — `reportRetainDays: 60`. Учёт баланса хранится **вне** очищаемых журналов.

## Управление

```powershell
.\terra-runner.ps1 -Once                # одна реальная итерация
.\terra-runner.ps1                      # автономный цикл
.\terra-runner.ps1 -DryRun              # проверка без трат
.\terra-runner.ps1 -Status              # текущий режим/расход/оценка остатка
.\terra-runner.ps1 -Stop                # мягко остановиться после итерации
.\terra-runner.ps1 -Abort               # прервать текущую итерацию на следующем опросе
.\terra-runner.ps1 -ClearStop           # снять оба флага
.\terra-runner.ps1 -MaxIterations 10    # ограничить запуск 10 итерациями
```

`-Stop`/`-Abort` из другого терминала, пока Runner работает. При `-Abort` возможно незакоммиченное состояние; перед следующим запуском проверь Git и результаты.

## Безопасность и ограничения

- Локальные бюджетные проверки **не гарантируют точный финансовый потолок**: отдельный запрос модели может закончиться после достижения порога.
- `stats --days 0` и `stats --all` суммируются по **всем** локальным проектам OpenCode, но не по всем внешним потребителям API-провайдера. Для OpenCode Console реальный остаток проверяется через UI Billing. Подробнее: https://dev.opencode.ai/v2/docs/console/billing
- Реальный баланс может измениться из-за пополнений, автоплатежей и трат на другом устройстве: snapshot нужно периодически сверять.
- Нельзя одновременно запускать два Terra Runner в одном `logs.root` благодаря global lock. Отдельные ручные OpenCode-сессии не блокируются и могут одновременно тратить средства.
- Любая непроверяемая стоимость, отсутствие нужной ветки Git, непроверенный push или незакоммиченные изменения приводят к остановке.
- Скрипт не выполняет реальных платежей и не отправляет пользовательские секреты от собственного имени; OpenCode-агент должен отдельно соблюдать свои ограничения.

При первом обновлении советуем: `selftest → DryRun → Once → цикл`. В окружении подготовки архива невозможно выполнить Windows PowerShell, поэтому результат `terra-selftest.ps1` на твоём ПК обязателен перед автономным запуском.
