# Erranix NTD — одна автономная итерация разработки

Ты работаешь над коммерческим SaaS Erranix NTD. Режим Build.

## Входные данные

Изучи `NTD-ROADMAP.md`, `NTD-PROGRESS.md`, актуальные исходники, профильные документы и последние коммиты Git. Рабочая ветка должна быть `codex/terra`. Источником требований является roadmap, а не история этого чата.

## Задача текущего запуска

1. Выбери **одну небольшую законченную логическую итерацию**: первую доступную невыполненную P0/MVP-задачу (или несколько тесно связанных) с выполненными зависимостями.
2. Реализуй полноценную функциональность без заглушек и фиктивных успехов; не переписывай архитектуру без необходимости.
3. Соблюдай PHP 8.4, PSR-4/12, MySQL, Composer, Tabler и принятые проектом стандарты.
4. Для каждого изменения проверь backend-авторизацию, ownership, CSRF/XSS/SQL, обработку ошибок; для критических переходов — атомарность и идемпотентность.
5. Добавь тесты; выполни доступные проверки. Не заявляй об успешном результате непроведённого теста.
6. Обнови `NTD-ROADMAP.md` (отметь `[x]` только реально завершённое) и добавь append-only запись в `NTD-PROGRESS.md`.
7. Проверь `git diff`, отсутствие секретов, создай один логичный Conventional Commit с ID задач и отправь в `origin/codex/terra`.
8. Если отсутствует remote или push отклонён, не используй force-push. Чётко зафиксируй проблему.

## Ограничения

- Не трогай main, другие проекты и production.
- Не выполняй реальные платежи и раскрытие конфиденциальных данных.
- Не удаляй чужие изменения и не применяй `git reset --hard`.
- Если нет проверяемой доступной задачи — явно напиши `NO_ACTIONABLE_TASKS`.
- Если внешние данные или критическое решение блокируют задачу, документируй причину, выбери независимую задачу, если возможно; иначе напиши `BLOCKED`.
- Не проси подтверждение на обычные действия разработки в рамках текущего проекта.

## Завершение

**После ОДНОЙ логической итерации остановись и заверши текущий запуск.** Не начинай следующую итерацию внутри той же сессии: внешний Terra Runner запустит её сам. Это важно для бюджета и контроля качества.

В финале кратко укажи: ID задач, что реализовано, результаты тестов, commit hash, результат push, блокеры и следующую задачу.
